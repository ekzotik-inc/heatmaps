# Новая настройка: полный обход мест

На этом проекте настройка «теряется» тремя способами, и каждый уже случался.
Пройти все пункты, даже если кажется, что поле простое.

## 1. Сохранение и восстановление

| Что | Где | Что сделать |
|---|---|---|
| Поле теплового слоя | `heatLayerSnapshot()` | добавить в объект |
| | `applyHeatLayerLook()` | восстановить с проверкой типа |
| Поле слоя точек | `pointLayerSnapshot()` | добавить в объект |
| | `applyPointLayersState()` | восстанавливается спредом, проверить дефолт |
| Поле записи точки | попадает в состояние вместе с `recs` | ничего |
| Простой глобальный параметр (число / флаг / строка) | `PLAIN_SETTINGS` | **одна строка**: ключ, тип, чтение, запись — и сохранение, и восстановление готовы |
| Параметр со своей логикой (миграция, проверка значения) | `buildStateSnapshot` + `applyViewState` | добавить в оба |

Производные поля (`nd`, `ld`, `lc`, `fil`, `stats`, `_shownCount`) в снапшот
**не пишем** — они пересчитываются при загрузке.

## 2. Отпечаток состояния

`stateFingerprint()` решает, отправлять ли состояние на сервер. С октября
2026 он берёт **весь снимок** (кроме `_v/_app/_savedAt/_date/_lazy`): записи
слоёв заменены их числом, записи ручных слоёв — целиком. Новое поле в
снимке попадает в отпечаток само, руками ничего добавлять не нужно.

Проверка — тест «saved state» в `test/app.e2e.test.js`: он меняет каждое
поле снимка и требует, чтобы менялся отпечаток. **Новое поле добавить в
`test/app-state.fixture.js`** (со значением не по умолчанию) — тогда тест
проверит и восстановление, и отпечаток. Запуск: `npm test`.

## 3. Перестроение UI

Слой участвует в нескольких списках. Забыть любой — он «не появится» там до
перезагрузки страницы.

- `buildHeatUI()` — карточки тепловых слоёв;
- `buildCustomPtUI()` — карточки слоёв точек;
- `buildAddrSrcSel()` — шаг 1 адресной программы;
- `buildAddrRefSel()` — шаг 2 (вызывается из `buildAddrSrcSel`);
- `buildRecBasisSel()` — основа рекомендаций;
- `buildRtExclUI()` — шаг 3, исключения;
- `updateLayerLegend()` / `updateCountBadge()` — легенда и счётчик;
- `rebuildUpTarget()` — цель загрузки во вкладке «Данные».

`focusNewLayer()` — общая точка после создания/перезаливки слоя, держать её
полной.

## 4. Пересчёты

- Изменился состав **наших точек** (слои вкладки «Точки», включая ручные) →
  `reenrichAll()`, иначе покрытие `nd` и рекомендации останутся по старому
  набору.
- Изменилась видимость/фильтр → `renderHeat()` сам обновит `_shownCount`,
  легенду и бейдж.

## 5. Ленивые записи

Записи тепловых слоёв грузятся только для видимых слоёв и основы рекомендаций.

- Судить о наполненности слоя — по `layerRecordCount(d)` (`stats.n`), **не** по
  `recs.length`.
- Перед чтением `recs` в расчётах — `await ensureLayerRecords(keys)`.
  Иначе получится правдоподобный, но неверный результат без признаков ошибки.

## 6. Если настройка влияет на числа

- В выгрузку числа идут через `exportNum()` (значащие цифры), не через
  округление до фиксированного знака.
- На экране — через `fmtVol(d, v)`, который учитывает единицу слоя (`volUnit`)
  и подбирает знаки по величине.
- Любой новый счётчик обязан совпадать с остальными по смыслу: бейдж = сумма
  строк легенды = нарисованное. Если счётчик про другое (например, видимую
  область) — это должно быть написано в подписи.
