# Выкатка правок

Порядок обязателен: пропуск версии кэша = владелец увидит старый код и решит,
что правка не сработала.

## 1. Версия кэша

Если менялись `app.js`, `style.css` или boot-скрипт в `index.html` — поднять
`?v=YYYYMMDD<буква>` **в обоих местах**:

```bash
grep -n "?v=2026" index.html          # текущие значения
sed -i 's/style.css?v=СТАРОЕ/style.css?v=НОВОЕ/; s/app.js?v=СТАРОЕ/app.js?v=НОВОЕ/' index.html
grep -n "?v=2026" index.html          # обе строки обновились?
```

Буква инкрементируется в пределах дня: `20260930a` → `20260930b`.

## 2. Проверки

```bash
node --check app.js
node --check server/server.js          # если трогал сервер
npx eslint --config <конфиг> app.js    # репозиторный .eslintrc устарел под ESLint 10
```

Лишние 11 ошибок вида `sessionStorage is not defined` / `DATA is already
defined` — артефакты временного конфига, а не реальные проблемы.

Дополнительно, если правил разметку:

```bash
python3 -c "
import re; s=open('index.html',encoding='utf-8').read()
for t in ['div','details','button','select','label']:
    o=len(re.findall(r'<'+t+r'[\s>]',s)); c=len(re.findall(r'</'+t+r'>',s))
    print(t, o, c, 'OK' if o==c else 'MISMATCH')"
```

И проверить, что все `id`, к которым обращается JS, существуют в разметке
ровно один раз.

## 3. Коммит и пуш

```bash
git pull --rebase origin main          # в репозиторий параллельно идут PR
git add -A
git commit -F - <<'MSG'
<Заголовок в повелительном наклонении, по-английски>

<Что было сломано или чего не хватало, потом что сделано и почему именно так.>

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
Claude-Session: <ссылка на сессию>
MSG
git push -u origin main
```

**Не использовать `-m` с текстом, где есть обратные кавычки** — bash выполнит
подстановку и испортит сообщение. Только heredoc или файл.

PR не создавать без явной просьбы владельца.

## 4. Что сказать владельцу

- **Всегда:** обновить страницу с Ctrl+Shift+R.
- **Если менялся `server/server.js`:** передеплоить сервер на Render — фронт на
  GitHub Pages обновится сам, сервер нет. Без этого новые эндпоинты вернут 404,
  и фича будет выглядеть сломанной.
- **Если менялась схема БД:** таблица создаётся на старте сервера
  (`CREATE TABLE IF NOT EXISTS`) — отдельной миграции не нужно, но передеплой
  обязателен.

## 5. Документация

После значимой правки обновить:

- `CONTEXT.md` — раздел по теме + версия кэша в шапке и в §3;
- `PROJECT_UPDATES.md` — запись `## YYYY-MM-DD — Заголовок` в конец;
- `FEATURES.md` — строки затронутых разделов и `Last updated`;
- `CLAUDE.md` — только если появилось новое **правило**, на котором можно
  сломаться.
