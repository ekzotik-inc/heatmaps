# Конфигурация Claude Code для этого проекта

```
.claude/
├── agents/     — субагенты: кому передать задачу целиком
└── skills/     — скилы: процедуры, которые повторяются каждый раз
```

Правила проекта, обязательные для всех, — в корневом `CLAUDE.md`.
Архитектура и модель данных — в `CONTEXT.md`.

## Скилы

| Скил | Когда |
|------|-------|
| `release` | После **любой** правки `app.js` / `style.css` / `index.html` / `server/`: версия кэша → проверки → коммит → пуш → что сказать владельцу |
| `state-inspect` | Жалобы «не сохраняется», «слои не загрузились», «сервер недоступен», коды 401/403/404: проверка живого сервера и состояния карты |
| `layer-setting` | Добавляешь поле слою, точке или параметр анализа: где сохранить, восстановить, учесть в отпечатке и какие списки перестроить |

Вызов: `/release`, `/state-inspect`, `/layer-setting` — или просто по смыслу
задачи, Claude Code подхватит их сам.

## Субагенты

| Агент | Когда вызывать |
|-------|----------------|
| `senior-engineer` | Сложные многошаговые задачи, архитектура, техдолг |
| `code-reviewer` | После правок, до коммита: регрессии, XSS, инварианты состояния |
| `security-auditor` | Перед релизом, при правках `server/`, `render.yaml`, CI |
| `frontend-ux` | Изменения интерфейса, доступность, адаптив |
| `performance-optimizer` | Тормоза, рост объёма данных, тяжёлые пересчёты |
| `geo-analyst` | Формулы тепла/рекомендаций, новые города и страны |
| `docs-keeper` | Документация разошлась с кодом |

Вызов: `используй агента code-reviewer для проверки последних правок`.

## Чем скил отличается от агента

**Скил** — это инструкция «как правильно сделать шаг», её выполняет текущая
сессия, контекст сохраняется. **Агент** — отдельный исполнитель с чистым
контекстом, ему отдают задачу целиком и получают вывод.

Процедуру (выкатить, продиагностировать, обойти чек-лист) — скилом.
Суждение (найди регрессии, оцени архитектуру) — агентом.
