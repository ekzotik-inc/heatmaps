# Heat Map · BR

Интерактивная тепловая карта торговых точек: загрузка слоёв из CSV/XLSX,
рекомендации по открытию новых точек BR, адресная программа и сводка по городу.
Интерфейс на русском. Страны: **Узбекистан** (карты `comdep`, `other`) и
**Кыргызстан** (карта `kg`).

Подложка карты — **2ГИС** (правило проекта, менять нельзя, см. `CLAUDE.md`).

## Стек

Без сборки — статические файлы:

- **Leaflet 1.9.4** + `leaflet.heat` — карта и тепло;
- **PapaParse** и **SheetJS (XLSX)** — разбор файлов, грузятся лениво при первой
  загрузке/выгрузке (~900 КБ не тратятся на старте);
- **Node/Express** — маленький сервер базы и состояний карт (`server/`).

| Файл | Назначение |
|------|-----------|
| `index.html` | Разметка, экран входа, выбор карты, boot-скрипт (загрузка базы + кэш) |
| `app.js` | Вся клиентская логика: карта, слои, тепло, анализ, состояние, авторизация |
| `style.css` | Стили и дизайн-токены (`:root`) |
| `server/server.js` | `/data`, `/state`, `/health` — файл или PostgreSQL |
| `render.yaml` | Деплой сервера на Render |
| `.claude/agents/` | Субагенты для работы над проектом (см. README внутри) |

## Запуск локально

```bash
# 1) сервер данных
cd server && npm install
# задайте API_KEY, SESSION_SECRET и AUTH_USERS_JSON в .env или окружении
node server.js   # :3001

# 2) фронт — любой статический сервер из корня репозитория
npx serve .        # или: python3 -m http.server 8080
```

По умолчанию фронт ходит на прод-сервер (`window._HM_SERVER_URL` в `index.html`).
Для локальной разработки временно поменяйте этот адрес на `http://127.0.0.1:3001`
(в коммит такое изменение не отправлять).

## Проверки перед коммитом

```bash
node --check app.js          # обязательно
node --check server/server.js
npm run lint                 # eslint
```

То же самое выполняет CI (`.github/workflows/ci.yml`) на каждый push и PR — плюс
проверяет, что при правке `app.js`/`style.css` поднята версия кэша в `index.html`.

## Деплой

- **Фронт** — GitHub Pages из ветки `main` (автоматически).
  **Важно:** при любой правке `app.js` / `style.css` / boot-скрипта поднимайте
  версию кэша `?v=YYYYMMDD<буква>` в `index.html` — в обоих местах (стиль и скрипт).
- **Сервер** — Render (`render.yaml`). Переменные окружения задаются в дашборде:
  - `API_KEY` — ключ записи, **в репозитории не хранится**;
  - `SESSION_SECRET` — ключ подписи HttpOnly-сессий;
  - `AUTH_USERS_JSON` — пользователи, роли и scrypt-хеши;
  - `ALLOWED_ORIGINS` — список разрешённых origin через запятую;
  - `DATABASE_URL` — PostgreSQL; без неё состояние пишется в файл и теряется
    при перезапуске инстанса.

## Наши точки

Вкладка «Точки» — это наша сеть: любой слой, загруженный туда (CSV/XLSX с
колонками `name, lat, lon` и опционально `addr, hours, code`), считается нашими
точками. От них считаются радиус покрытия в рекомендациях, расстояния в адресной
программе и метрика «Курильщиков на 1 нашу точку». Отдельного зашитого набора
IQOS BR / 2nd SE больше нет — у каждой карты свои точки, они хранятся в её
состоянии.

## Права доступа

Вход проверяется сервером через `/auth/login`. Пользователи и роли задаются в
`AUTH_USERS_JSON` на сервере, пароли хранятся только как scrypt-хеши. После входа
браузер получает подписанную HttpOnly-сессию; `/data` и `/state` без неё недоступны.

Запись общей базы и состояния доступна только роли `admin` и дополнительно
защищена `API_KEY`. Ключ записи вводится один раз в «Данные → Доступ к записи» и
хранится только в браузере владельца (`localStorage`). Инструкции по созданию
хеша: `node server/create-password-hash.js "новый-пароль"`.
