# Правила проекта «Тепловая карта»

Статический фронтенд (ванильный JS + Leaflet, без сборки) на GitHub Pages +
крошечный Express-сервер состояния на Render. Полный контекст — `CONTEXT.md`,
**прочитать перед работой**. История изменений — `PROJECT_UPDATES.md`.

---

## ⛔ Базовая карта — ТОЛЬКО 2ГИС. НИКОГДА не менять.

Подложка в `app.js` — **2ГИС**. Провайдер не меняется: **запрещено** ставить
CARTO, OSM, Mapbox или любой другой — при редизайнах, по референсу со
скриншота, из-за ошибок загрузки. Меняется только по прямой явной просьбе
владельца именно про подложку карты.

**Какой именно эндпоинт 2ГИС — зависит от ключа** (`window._HM_2GIS_KEY` в
`index.html`):

- ключ задан → `https://tile{s}.maps.2gis.com/v2/tiles/online_hd/{z}/{x}/{y}.png?key=…`,
  субдомены `01234` — поддерживаемый Raster Tiles API;
- ключа нет → старый `https://tile{s}.maps.2gis.com/tiles?x={x}&y={y}&z={z}&v=1`,
  субдомены `0123`.

**История, чтобы не ходить по кругу.** В сентябре 2026 подложку подменили на
OSM с формулировкой «deprecated endpoint» — проверка показала 200 и детальный
тайл 70 КБ, замена была необоснованной, 2ГИС вернули. В октябре 2026 2ГИС
**действительно** начал выводить старый эндпоинт из эксплуатации и подменять
тайлы заглушкой «сервис более не поддерживается», порегионально (владелец в
Ташкенте видел заглушку, тот же тайл из CI-контейнера приходил нормальным).
Вывод: **проверять содержимое тайла, а не только HTTP-код**, и при реальной
поломке переходить на новый эндпоинт 2ГИС, а не на чужого провайдера.

## Обязательное при каждой правке

- **Версия кэша.** Правишь `app.js` / `style.css` / boot-скрипт — поднимаешь
  `?v=YYYYMMDD<буква>` в `index.html` **в обоих местах** (style.css и app.js).
- **`node --check app.js`** (и `node --check server/server.js`, если трогал
  сервер) до коммита.
- **`git pull --rebase origin main` перед пушем** — в репозиторий параллельно
  идут PR, конфликты реальны.
- Пуш — **в `main`**. PR не создавать без явной просьбы.
- Дизайн-токены — только из `:root` в `style.css`, новые цвета не вводить.

## Инварианты, на которых уже ломались

1. **Новое поле слоя/точки → три места, иначе оно «не доезжает»:**
   `buildStateSnapshot` (сохранить) + `applySnapshot` (восстановить) +
   **`stateFingerprint`** (учесть в отпечатке). Пропуск отпечатка = правка не
   уходит на сервер, потому что состояние считается неизменным. Так дважды
   терялись правки карточек ручных точек и цвет точки.
2. **Новый слой → перестроить ВСЕ зависимые списки:** `buildHeatUI`,
   `buildAddrSrcSel`, `buildRecBasisSel`, `buildRtExclUI`. Пропуск любого —
   слой «не появляется» в соответствующем шаге до перезагрузки.
3. **Записи тепловых слоёв грузятся лениво.** Нельзя судить о пустоте слоя по
   `recs.length` — бери `stats.n` (`layerRecordCount`). Перед чтением `recs`
   дождись `ensureLayerRecords(keys)`, иначе молча посчитаешь по пустому
   массиву и покажешь правдоподобный неверный результат.
4. **Принадлежность городу — только через `recInSelection(r)`.** Два разных
   пути (строка `fil` против геометрии) однажды уже разошлись.
5. **Числа в выгрузку — `exportNum()` (значащие цифры), не округление до
   фиксированного знака.** `Math.round(v*1000)/1000` превращал доли 0,00042 в
   одинаковые 0,001.
6. **Одно число — один смысл.** Бейдж «Точек на карте» = сумма строк легенды =
   то, что реально нарисовано (`_shownCount`). Счётчик ярлыков считает видимую
   область и обязан это проговаривать в подписи.
7. **Бинарные данные (фото) в состояние не кладём** — только идентификаторы,
   байты на сервере (`/photo`). Состояние уходит целиком на каждое сохранение.
8. **XSS:** всё из загруженных файлов и имён слоёв — через `esc()` перед
   `innerHTML`, попапами и тултипами.
9. **Leaflet-слои чистим перед перерисовкой** (`clearLayers` / `removeLayer`),
   иначе остаются осиротевшие маркеры, которые нельзя выключить.
10. **KG-карта — без наших точек.** Никаких делений на ноль, `Infinity` и
    «1e15 км» в подписях: если ориентиров нет, пишем «—» и объясняем.

## Сервер

- Запись (`POST`) требует роль `admin` **и** заголовок `X-API-Key`. Ключ
  **выдаётся сервером при входе** (`writeKey` в ответе `/auth/login` и
  `/auth/me`) — владелец ничего не вводит. Статический `API_KEY` из окружения
  продолжает работать для скриптов.
- Правка `server/server.js` требует **передеплоя на Render** — фронт на Pages
  обновится сам, сервер нет. Обязательно сказать об этом владельцу.
- Секреты — только в переменных окружения Render. В репозиторий не коммитим
  ни данные карт, ни `.env`, ни фото (`.gitignore`).
