# CONTEXT — Heat Map · BR (проектная память для новой сессии)

Прочитав этот файл, ассистент должен понимать архитектуру, модель данных,
решения и подводные камни без повторного расследования. Обновлять при
существенных изменениях. Актуально на: версия кэша **20260704h**.

---

## 1. Что это

Веб-приложение — интерактивная **тепловая карта торговых точек**. Пользователь
грузит слои данными (CSV/XLSX), видит heat map, получает **рекомендации** по
открытию новых точек BR, работает с **адресной программой** (фильтры по
расстоянию/объёму/исключениям) и смотрит **сводку по городу**. Интерфейс на
русском.

- **Карты (независимые):** `comdep`, `other` — Узбекистан; `kg` — **Кыргызстан**.
- Стек: **Leaflet** + плитки **2ГИС**, тепло — `leaflet.heat`, парсинг файлов —
  PapaParse + XLSX (SheetJS, грузятся лениво). Всё **без сборки** — статические файлы.
- Хостинг: **фронт — GitHub Pages**, **сервер данных — Render** (Node/Express).

## 4. Сервер и данные

- Прод-сервер: `https://hm-server-xpg0.onrender.com` (`window._HM_SERVER_URL` в
  index.html). Тариф Render — **платный** (не засыпает).
- `GET /data` — базовый датасет (ключ `dataset`), всем на старте, read открыт.
- `POST /data` — заменить базу (нужен `X-API-Key`) — кнопка «Сохранить базу».
- `GET/POST /state?map=comdep|other|kg` — общее состояние карты. GET открыт,
  POST — по ключу.
- `GET /health` — health-check.
- `MAPS = ['comdep','other','kg']` в server.js. `storeKey()` в localStorage =
  `hm_state_<currentMap>`.
- **Структура `DATA` (из `/data`, ~1.6 МБ):** `own` (наши точки BR/IQOS),
  `cities`, `cig`, `sticks`, `districts` (районы Ташкента с `tier` дохода),
  `field` (грид дохода Ташкента). База **UZ-специфична и общая для всех карт**
  (см. §5 про KG-ограничение). `combined` больше не хранится — выводится на
  клиенте (`baseDemandRecs`).

## 5. Карты и страны (UZ / KG)

- **Пер-страновой конфиг** `COUNTRIES` (app.js): у каждой страны свой список
  городов (плашка сверху), центроиды (`cityOf`), справочник вкладки «Город»
  (`UZ_STATS`/`KG_STATS`), доля курящих, валюта зарплаты (`wageUnit/wageCur`).
- `MAP_COUNTRY` привязывает карту к стране; **`applyCountry(currentMap)`
  вызывается первым в `startApp`** и заполняет
  `CITIES/CC/CITY_CENTERS/CITY_STATS/SMOKE_*/WAGE_*`.
- **KG-данные (2025):** население — Нацстатком КР (stat.gov.kg); зарплаты по
  регионам за 2025 (тыс. сом/мес); курение — ВОЗ 2024 (муж. 32,8%, жен. 2,9%).
  Города: Бишкек, Ош, Джалал-Абад, Каракол, Токмок, Узген, Нарын, Талас, Баткен.
- **Ограничение KG:** база (`own`/cig/sticks/districts) — UZ и общая. На KG-карте
  `own` пуст для KG-городов → метрика «на 1 нашу точку» = «—», а «расстояние до
  наших точек» в адресной не работает, пока не добавят KG-точки (слой «Свои
  точки» как референс или загрузка «Наши точки»). Тепловые слои и рекомендации
  по загруженным слоям работают. «Районы» скрыты вне UZ; KG-карта центрируется
  на Бишкеке.

## 6. Модель слоёв

- **Главная вкладка «Карта» показывает только загруженные пользователем слои**
  (`heatKeys` = ключи `custom_*`). Стартует пустой со заглушкой.
- `cig`/`sticks` остаются в `DS`, но **не в `heatKeys`** — не рисуются/не в списке
  (данные для служебных нужд).
- **Загрузка:** «Загрузить слой (файл)» → CSV/XLSX → модалка (имя + цвет) → слой
  из файла (`enrich(toRecs(rows))`) → в `heatKeys`, карта подлетает к данным.
- **Карточка слоя:** вкл/выкл, палитра, цвет, интенсивность, прозрачность,
  ✎ переименовать, ⬆ Обновить данные, × удалить (с `confirm`).
- Колонки файла: `name, lat, lon, value` (+опц. `addr, code, hours`). `value` →
  `vol` (яркость тепла). Нет `value` → `vol=1`.
- Ключевые функции: `buildHeatUI`, `renderHeat`, `confirmLayerModal`/
  `openLayerModal`/`parseSheet`/`focusNewLayer`, `toRecs`/`enrich`.
- **Парсинг файлов ленивый** (`ensureSheetLibs`); все загрузки через `parseSheet`
  (try/catch + тост «Обработка файла…»).

## 7. Рекомендации и Адресная программа (вкладка «Анализ»)

Обе работают **по загруженным слоям** (не по cig/sticks).
- **Рекомендации:** `#rec-basis-sel` — выбор слоя-основы (`recBasis`).
  `renderRecs()`: `DS[recBasis].recs`, фильтр по городу и `s.nd > covR`
  (расстояние до ближайшей нашей BR/IQOS), жадное подавление, топ-N.
- **Адресная:** источник (`addrSrcKey`) = heat-слой или слой своих точек
  (`__cpt__`). `__shipment__` удалён. Референс — `__own__` (BR/IQOS) или слой
  своих точек. `runAddrFilter`/`previewAddrOnMap`/`exportRetraffic`.
- Селекторы перестраиваются при изменении слоёв (`buildRecBasisSel`+`buildAddrSrcSel`).

## 8. Города и `cityOf`

- `cityOf(lat,lon)` → ближайший центроид из `CC` (заполняется `applyCountry`:
  из `DATA.cig.recs` где есть, иначе хардкод-центры страны).
- При загрузке состояния `fil` каждой точки **пересчитывается** (cityOf) — чинит
  старые слои. Выбор города сверху фильтрует тепло/рекомендации/адресную;
  `fitView()` летит к данным города.

## 9. Интенсивность тепла

`renderHeat()`: каждый слой нормируется **по своему p90** (магнитуда `value` не
важна), gamma-подъём `t^0.55` + порог `0.18` (слабые точки видны). Ползунок
«Интенс.» (`d.intensity`) — множитель. Глобальная «Общая яркость» (`heatBoost`)
через прозрачность canvas (`applyHeatCanvas`/`restyleHeatCanvases`).

## 10. Свои точки (вкладка «Точки»)

`customPtLayers` — слои маркеров (не тепло): форма/цвет/радиус охвата, рендер в
`cptRoot` (полностью чистится каждый рендер — защита от осиротевших групп). Могут
служить референсом/исключением в адресной.

## 11. Вкладка «Город»

`renderCityInfo()` (вызывается из `updateAccBadges`). Город не выбран → подсказка.
Выбран → карточки: население, тайлы (21+, курильщики 21+, средняя зарплата,
курящие мужчины), блок «На карте сейчас» — **только строка «Курильщиков на 1 нашу
точку»** (по просьбе владельца), «Выводы для бизнеса». Данные страны — `CITY_STATS`
(активной страны), курение — `SMOKE_M/F/AVG`, валюта — `WAGE_UNIT/WAGE_CUR`.

## 12. Состояние и синхронизация

- Автосейв (debounce 400 мс) → `doSave` → localStorage + `pushToServer`.
  `buildStateSnapshot()`/`applySnapshot()`.
- **Slim-recs (важно):** в состоянии хранятся **только входные поля точек**
  (`lat/lon/vol` + `name/addr/code/hours`, координаты округлены), а `nd/ld/lc/fil`
  и `stats` **пересчитываются при загрузке** (`slimRecs` на сохранении, `cityOf`+
  `enrich`+`statsOf` на загрузке). Причина: состояние разрослось до ~7 МБ и POST
  перестал проходить («Сервер недоступен» при живом сервере) — slim ужимает ~вдвое.
- **Анти-клоббер при гидрации:** `startApp` выбирает local/server по таймстампу,
  но **не даёт пустому источнику затереть слои** непустого (`hasLayers`). Если у
  пользователя «пропали» слои — они на сервере; помогает hard refresh или
  `localStorage.clear()` в консоли.
- Кэш датасета: boot-скрипт кэширует `/data` в `localStorage['hm_dataset_cache_v1']`
  (stale-while-revalidate). localStorage близко к лимиту (~5 МБ) — записи в
  try/catch, при переполнении просто не кэшируется.

## 13. Безопасность

- **Запись на сервер — только у владельца.** Ключ **не в бандле** — вводится в
  «Данные → Доступ к записи», хранится в `localStorage['hm_admin_key']`.
  `pushToServer`/`pushDataset` требуют `isAdmin() && SERVER_KEY`; сервер проверяет
  `X-API-Key == API_KEY` (env на Render). **Действие владельца:** задать `API_KEY`
  на Render и ввести то же в браузере; старый ключ считать утёкшим.
- **XSS:** пользовательские значения экранируются `esc()` перед вставкой в
  innerHTML/попапы/тултипы/`<option>`.
- **Файлы не в git:** данные живут на сервере + в браузере; `.gitignore` исключает
  server/state\*.json, .env, dataset-дампы.
- Глобальный обработчик ошибок (`error`/`unhandledrejection` → лог + тост).
  Полноценный Sentry — когда будет DSN.
