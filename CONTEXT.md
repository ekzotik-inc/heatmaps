# CONTEXT — Heat Map · BR (проектная память для новой сессии)

Этот файл — краткая, но полная передача контекста. Прочитав его, ассистент
должен понимать архитектуру, модель данных, недавние решения и подводные камни
без повторного расследования.

---

## 1. Что это

Веб-приложение — интерактивная **тепловая карта торговых точек по Узбекистану**
(Ташкент, Андижан, Бухара, Самарканд, Коканд, Фергана, Навои). Пользователь
грузит слои данными (CSV/XLSX), видит heat map, получает **рекомендации** по
открытию новых точек BR и работает с **адресной программой** (фильтрация точек
по расстоянию/объёму/исключениям). Интерфейс на русском, ВЕСЬ UI в UPPERCASE
(`text-transform: uppercase` на body — это осознанный стиль, не трогать).

Карта: Leaflet + плитки 2ГИС. Тепло: `leaflet.heat`. Парсинг файлов: PapaParse
(CSV) и XLSX (SheetJS). Всё без сборки — статические файлы.

## 3. Git / деплой

- **Разработка и пуш — прямо в `main`** (так распорядился владелец). Ветки-фичи
  не используем.
- Render авто-деплоит статику из `main`. Сервер — отдельный сервис на Render.
- **Кэш-бастинг:** `index.html` ссылается на `style.css?v=YYYYMMDD<буква>` и
  грузит `app.js?v=...` тем же тегом. **При любом изменении app.js/style.css/boot
  нужно поднять букву версии** (сейчас `20260629l` → следующий `...m`). `index.html`
  отдаётся с `no-cache`, поэтому свежий тег доезжает сразу; пользователю всё равно
  советуем hard refresh (Ctrl+Shift+R).
- Коммиты заканчивать:
  `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>` (без модельного ID в артефактах).

## 4. Сервер и данные

- Прод-сервер: `https://hm-server-xpg0.onrender.com` (задан в `index.html` как
  `window._HM_SERVER_URL`). Ключ записи `window._HM_SERVER_KEY` (лёгкий гейт, виден в бандле).
- `GET /data` — базовый датасет (ключ `dataset`), отдаётся всем на старте. Read открыт.
- `POST /data` — заменить базу (только с `X-API-Key`). Триггерится кнопкой
  «Сохранить базу на сервере» (вкладка «Данные», админ).
- `GET/POST /state?map=comdep|other` — общее состояние конкретной карты.
- `GET /health` — health-check (для keep-warm).
- Две независимые карты: `comdep` и `other` (выбор после логина). `storeKey()` в
  localStorage = `hm_state_<currentMap>`.

**Структура `DATA` (из `/data`), ~2.45 МБ:**
`own` (наши точки BR/IQOS), `cities` (массив рус. названий), `cig`, `sticks`,
`combined` (слои отгрузок — см. ниже), `districts` (полигоны районов Ташкента с
`tier` дохода), `field` (грид дохода Ташкента). `cig`/`sticks`/`combined` — это
`{recs:[{lat,lon,vol,fil,...}], stats:{...}}`.

## 5. Модель слоёв (ВАЖНО — недавно переделано)

Раньше на главной вкладке были зашитые слои Сигареты/Стики/Оба. **Сейчас:**

- **Главная вкладка («Карта») показывает только загруженные пользователем слои**
  (`heatKeys` содержит только ключи `custom_*`). Стартует пустой со заглушкой.
- **`cig`/`sticks`/`combined` остаются в `DS`, но НЕ в `heatKeys`** — не рисуются
  и не в списке. Живут как данные для служебных нужд (исторически — Анализ; сейчас
  Анализ переведён на загруженные слои, но объекты оставлены, вреда нет).
- **Загрузка слоя:** кнопка «Загрузить слой (файл)» → выбор CSV/XLSX → модалка
  спрашивает **имя + цвет** → слой строится из файла (`enrich(toRecs(rows))`),
  добавляется в `heatKeys`, карта подлетает к данным.
- **Карточка слоя:** вкл/выкл, палитра (ramp), цвет, интенсивность, прозрачность,
  **✎ переименовать** (инлайн-инпут), **⬆ Обновить данные** (перезалить файл в
  этот слой), **× удалить**.
- Ожидаемые колонки файла: `name, lat, lon, value` (плюс опц. `addr, code, hours`).
  `value` → «объём» (`vol`), определяет яркость тепла. Если `value` нет — `vol=1`.

Ключевые функции: `buildHeatUI()` (карточки), `renderHeat()` (рендер тепла),
`confirmLayerModal()` / `openLayerModal()` / `parseSheet()` / `focusNewLayer()`
(создание слоя из файла), `toRecs()` / `enrich()` (парсинг + обогащение).

## 6. Рекомендации и Адресная программа (вкладка «Анализ»)

Обе **работают по загруженным слоям** (не по cig/sticks).

- **Рекомендации:** выпадающий `#rec-basis-sel` — выбор слоя-основы спроса
  (`recBasis` = custom-ключ). `renderRecs()` берёт `DS[recBasis].recs`, фильтрует
  по городу и по `s.nd > covR` (расстояние до ближайшей нашей BR/IQOS точки),
  жадно подавляет близкие кандидаты, показывает топ-N зон. `buildRecBasisSel()`
  перестраивает список при изменении слоёв.
- **Адресная программа:** источник (`addrSrcKey`) = загруженный heat-слой или
  слой своих точек (`__cpt__<id>`). Источник `__shipment__` (cig+sticks) удалён.
  Фильтры: расстояние до референса (`__own__` = BR/IQOS, либо слой своих точек),
  объём точки, исключения (точки рядом с другими слоями). `runAddrFilter()`,
  `previewAddrOnMap()`, `exportRetraffic()`.
- Оба селектора перестраиваются при загрузке/обновлении/переименовании/удалении
  слоя (вызовы `buildRecBasisSel()` + `buildAddrSrcSel()`).

## 7. Города и `cityOf` (недавний фикс «только Ташкент»)

- `CITIES` = `DATA.cities` (рус. названия). Верхняя плашка городов из них.
- `cityOf(lat,lon)` относит точку к **ближайшему центроиду города** из `CC`.
- `CC` строится из данных `DATA.cig.recs` по городам, а для недостающих —
  **фолбэк `CITY_CENTERS`** (хардкод координат всех 6 городов + Навои). Это
  чинит ситуацию, когда база на сервере содержит cig-данные только по Ташкенту.
- При загрузке состояния (`applySnapshot`) `fil` каждой точки **пересчитывается
  по координатам** — чинит старые слои, где `fil` был проставлен старым cityOf.
- Выбор города сверху фильтрует тепло, рекомендации, адресную; `fitView()` летит
  к данным выбранного города.

## 8. Интенсивность тепла (недавний фикс)

`renderHeat()`: каждый слой нормируется **по своему p90** (магнитуда `value` не
важна — слой с крошечными значениями виден так же, как с большими), затем
**gamma-подъём** (`t^0.55`) и минимальный порог `0.18`, чтобы слабые точки не
пропадали. Ручной ползунок «Интенс.» (`d.intensity`) — множитель поверх (fine-tune).
Есть глобальная «Общая яркость тепла» (`heatBoost`) — применяется через прозрачность
canvas в `applyHeatCanvas`/`restyleHeatCanvases`.

## 9. Своя точки (вкладка «Точки»)

Отдельная от heat-слоёв фича: `customPtLayers` — слои маркеров (не тепло). Грузятся
файлом, имеют форму/цвет/радиус охвата, рендерятся в родительскую группу `cptRoot`.
`renderCustomPoints()` полностью чистит `cptRoot` каждый рендер (защита от
«осиротевших» групп — был баг, что старые/новые маркеры накладывались и не
выключались). Могут служить референсом/исключением в адресной программе.

## 10. Прочее

- **Кнопка «Районы»** (плашка сверху) рисует полигоны `DATA.districts` (только
  Ташкент, покрашены по `tier` дохода). Была попытка добавить карту достатка по
  другим городам через Meta RWI — **откатили** по просьбе владельца. Осталось
  только для Ташкента.
- **Зум:** дефолтный контрол Leaflet отключён (`zoomControl:false`). Кастомный
  стеклянный блок справа (`#zoom-ctl`): +, −, «по размеру» (`fitView`). Кнопки
  гаснут на min/max зуме.
- **Boot/кэш:** boot-скрипт в `index.html` кэширует датасет в
  `localStorage['hm_dataset_cache_v1']` (stale-while-revalidate) — повторные
  заходы мгновенные. Плюс keep-warm workflow против холодного старта Render.
- **Состояние** автосохраняется (debounce) в localStorage и на сервер
  (`saveState`→`doSave`→`pushToServer`). `buildStateSnapshot()`/`applySnapshot()`.
- **Роли/логин:** клиентские креды в `initAuth()` (лёгкий гейт). Роль `viewer`
  прячет админ-контролы через `body.viewer` в CSS.

## 11. Подводные камни / договорённости

- **НЕ трогать** принудительный uppercase — это стиль.
- При изменении app.js/style.css/boot — **поднимать версию кэша** в `index.html`.
- Пуш — только в `main`. PR не создавать без явной просьбы.
- Экспорт адресной больше не делит на сиг/стики (общий объём слоя).
- В «Данные → Слой для загрузки» (`up-target`) теперь только «Наши точки» +
  загруженные слои (cig/sticks там больше нет).
- Владелец итеративно просит правки и сразу проверяет на проде — держать изменения
  безопасными и обратимыми, проверять `node --check app.js`, балансы тегов/скобок.

## 12. История ключевых правок (свежие → старые)

- Авто-нормализация интенсивности по слою + фолбэк-центроиды городов + пересчёт
  `fil` при загрузке (фикс «только Ташкент»).
- Рекомендации и адресная переведены на загруженные слои (убран `__shipment__`,
  кнопки основы → выпадающий список).
- Модель слоёв: главная вкладка только из файлов, rename + update на карточке;
  cig/sticks/combined скрыты.
- Ускорение загрузки: кэш датасета в localStorage + keep-warm workflow.
- Кастомный zoom-контрол.
- Фикс загрузки слоя, скрытого фильтром города (сброс на «Все» + подлёт).
- Редизайн: больше воздуха, сворачиваемые группы `<details>`.
- Фикс «своих точек»: `cptRoot`, чтобы маркеры не осиротевали/не накладывались.
- Карта достатка по RWI для регионов — добавлена и откачена (осталась только
  Ташкент-разбивка «Районы»).
